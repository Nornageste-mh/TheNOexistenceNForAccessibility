0.0.0.6: 修复导航顺序与画面对不上 —— 控件坐标恒为 0

玩家报告：上下光标导航的顺序和画面对不上，按下光标反而跳到画面上方。

日志给出了直接证据：

    [组 1 ★当前] Naninovel<Runtime>/UI/ControlUI/Buttons  项数=2
      #1 SettingsButton，按钮   [行=0 顶=0 左=0]
      #2 HistoryButton，按钮    [行=0 顶=0 左=0]

所有控件的坐标都是 0。排序拿到的位置全为 (0,0)，全部并列，
于是退化成按层级路径排 —— 顺序自然和画面对不上。

根因是**本项目第三个 IL2CPP 静默失败**，与之前的 as/is 同源：

    rt.GetWorldCorners(_corners);   // _corners 是托管 Vector3[]

托管数组传给原生方法时会被**拷贝**过去，原生写入的结果不会回流，
所以 _corners 一直是全 0，而且不报错。必须用 Il2CppStructArray<Vector3>。

这个 bug 影响面比表面大：
- 排序全部并列 -> 上下键顺序错乱（玩家看到的症状）
- 可见性判断里的「屏幕矩形是否相交」恒真 —— 那道检查一直形同虚设，
  全靠后面的 UI 射线兜着

顺带修掉排序器的第二个隐患：原来的比较函数用
    if (Mathf.Abs(a.Left - b.Left) > 0.01f) ...
拿「近似相等」当分支条件，不满足传递性。List.Sort 用的是内省排序，
比较函数只要不满足传递性，结果就是任意的（同样不报错）。
改成严格字典序：行 -> 列 -> 渲染层级。
